# Phase 6: Documents, extraction and voice input

## What was built
- **BusinessDocument API** (`/api/documents`): upload, list (search, category, status, pagination), get, update title/category, download (attachment), analyze (AI extraction), review (confirm or reject), archive.
- **Upload security:** type is decided from the first bytes and the allowed extension (must match). Allowed: PDF, PNG, JPEG, WebP, DOCX, XLSX, CSV, TXT, MD. Maximum 10 MB. Storage keys are generated by the server (`documents/<orgId>/<id>.<ext>`) and every path is checked to stay inside `UPLOAD_DIR`. Original names are only used as display titles after stripping path parts and control characters.
- **Duplicates:** the same bytes in the same organization return 409 with the existing document id. Analysis is claimed atomically, so two requests cannot run the model twice.
- **Extraction (OCR-style):** `POST /api/documents/:id/analyze` sends the file to the AI service `/extract` endpoint with a fixed instruction. The document is treated as untrusted data. The model's output is sanitised field by field: malformed amounts, dates and currencies become `null`, unknown keys are dropped, line items are capped at 100. Status becomes `REVIEW_REQUIRED`.
- **Review:** `POST /api/documents/:id/review` with `CONFIRM` (stores reviewed fields, status `COMPLETED`) or `REJECT` (status `FAILED`). A reviewer can correct fields before confirming. Only one reviewer decision can apply (conditional update).
- **Voice input:** a microphone button in Ask TIBEB AI using the browser's Web Speech API. Listening starts only on a button press. The transcript goes into the text box for review; nothing is sent automatically.
- **Audit:** upload, download, update, analyze, failed analyze, review and archive are recorded in `AuditEvent`.

## What it deliberately does NOT do
- It never creates a sale, expense, purchase, supplier payment or customer payment from extracted data. Those still require the normal authorized workflows.
- Archive never deletes files or rows. Hard deletion is not implemented, so no retention promise beyond "archived is hidden from lists".
- No antivirus or malware scanning is implemented. Do not describe uploads as scanned.
- No background queue. Analysis is a bounded request/response call with a 120 second timeout. A run stuck in `PROCESSING` for more than 5 minutes can be claimed again.
- Voice input uses the browser's speech service, not a backend transcription provider. Amharic support depends on the browser. Audio is not stored by this app.
- Extracted fields are never a financial record. The Ask TIBEB AI assistant does not yet read stored documents by id; it still takes attachments directly.

## Required setup
1. Schema: `BusinessDocument` gained status, hash, size, link and review fields, plus the `DocumentStatus` enum. This repo has no migration history yet, so create the first migration as in the existing setup: `cd apps/api && npx prisma migrate dev --name init` on a fresh or disposable database. On an existing database, review the diff first and take a backup.
2. Environment: no new variables. Uses `AI_SERVICE_TOKEN`, `AI_SERVICE_URL`, `UPLOAD_DIR` and the configured AI provider (`AI_PROVIDER`). Without a provider, extraction ends as FAILED with "The AI model is not configured".
3. Production storage: local disk under `UPLOAD_DIR`. Back it up with the database. Move to object storage before multi-server deployment.

## Tests
- `apps/api/src/documents/document-rules.spec.ts`: type detection (including disguised files), title and storage-key safety, status transitions, extraction sanitising, JSON parsing. Run with `npm test`.
- Controller tests (cross-tenant access, duplicate handling, review permissions) are NOT yet written. Add them with a test database before go-live.
